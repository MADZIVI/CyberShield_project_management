Project Scope

Defines the boundaries, deliverables, and limitations of CyberShield. Ensures all stakeholders clearly understand what is included and prevents scope creep during development.

In-Scope

  • Needs assessment and gap analysis of current security posture
  • Procurement and installation of SIEM software (Microsoft Sentinel)
  • Integration with existing network infrastructure and endpoints
  • Development of incident response playbooks
  • Staff cybersecurity awareness training program
  • System testing, documentation, and handover

Out-of-Scope

  • Physical security upgrades (e.g. access control systems)
  • Development of new business applications
  • Ongoing managed security services post-handover
  • Security audits of third-party vendors

Scope Control

  • Weekly progress and scope review meetings
  • Formal approval required for any scope changes
  • Clear documentation of all requirements and deliverables
  • Change control process approved by Project Sponsor

Success Criteria

  • The system meets all defined functional requirements
  • Key features (threat detection, alerts, compliance) operate correctly
  • The system is tested and validated by end users
  • All deliverables completed within the given timeframe
